# MadCop 用户场景文档

**用途**：本文件为 MadCop 项目（独立开发、本地优先的 AI 编程搭档）配套的简历、面试、自我介绍提供详实可考的使用场景与故事。所有场景都基于代码中**已经实现**的功能，不夸大、不虚构。

> ⚠️ **写作原则**：本文档强调**诚实**。我们不在面试材料里说 AI "自动修 bug" 或 "像人一样聪明"——这些是夸大。MadCop 的真实能力是"主动观察 + 经验沉淀 + 隐私优先"，下面所有故事都建立在这三个核心能力上。

MadCop 的目标用户有 6 类，每类用户用 MadCop 的频率和价值不同：

| 角色 | 最高频场景 | 长期价值 |

| 运维 / SRE | on-call 告警 | 事故复盘 SKILL.md |

## 二、3 个"最高频"使用场景

### 场景 A：开发时遇到报错（最高频，每天多次）

**用户痛点（不用 MadCop 时）**：
```
1. 跑 pytest 报错
2. 看 terminal 错误信息
3. 复制错误 → 打开 ChatGPT → 粘贴 → 等回复
4. 复制建议 → 回 terminal 试
5. 重复 5-10 次
```

**MadCop 流程**：
```
写代码/跑命令（不需要切窗口）
  ↓
5 分钟内 toast 弹窗
  ↓
直接点建议执行
```

**节省时间**：每次报错节省 5-10 分钟，每天 5-10 次 = 每天 25-50 分钟。

**真实示例**：
- 跑 `pytest` → 报 `ModuleNotFoundError: No module named 'httpx'`
- MadCop 弹窗："测试失败：httpx 模块没装。建议：pip install httpx"
- 跑 `tsc` → 报 `error TS2304: Cannot find name 'Xxx'`
- MadCop 弹窗："编译错误：未定义 Xxx。建议：检查 import 语句"
- 跑 `pytest` → 报 `FAILED test_xxx - AssertionError`
- MadCop 弹窗："测试失败。建议：检查断言条件"

**关键诚实点**：Observer 只能识别**错误信号关键字**（FAILED、error、ModuleNotFoundError、Traceback 等），**不做** code review（不读 diff、不理解代码逻辑）。所以"发现 bug"是真的，"修复 bug"是 LLM 帮你修，MadCop 帮你的是"看到 bug"。

---

### 场景 B：跨项目知识复用（最高价值，每月多次）

**用户痛点**：
- 这个月写 Vue 项目
- 下个月写 React 项目
- 又下个月写 Svelte
- 每次都"从零开始"——告诉 AI 项目背景、技术栈、命名约定

**MadCop 流程**：
```
Vue 项目第 1 天：写组件、踩坑 → SKILL.md 自动存档
  ↓
React 项目第 1 周："按上次的来"
  ↓
SKILL.md 自动检索 + 知识图谱补全
  ↓
3 周后，MadCop 已经"懂"了 30+ 通用模式
```

**真实示例**：
- 第一次写 FastAPI 端点 → MadCop 存了 SKILL.md "FastAPI 端点开发模式"
- 3 个月后写另一个 FastAPI 项目 → MadCop 自动调用这个 SKILL.md，无需重新描述
- 跨项目知识图谱自动连接："FastAPI 端点"和"PostgreSQL 集成"被关联起来
- 下次查询相关问题时，AI 已有跨项目的概念网络

**关键诚实点**：这种"知识积累"是**事实**——SKILL.md 真的保存在 `~/.madcop/skills/`，知识图谱真的存在 SQLite 中。但"AI 越用越聪明像人一样"是夸大——它是**结构化数据的检索增强**，不是真正的智能。

---

### 场景 C：写报告/研究（中等频率，每月 1-2 次）

**用户痛点（用 ChatGPT 写报告）**：
- AI 经常"编造"研究数据，看起来对但实际是 hallucination
- 写完报告还要一个个去查证引用
- 担心发出去被人指出错误

**MadCop 流程**：
```
1. 用户："写一份 2025 年 AI 编程工具市场分析"
2. MadCop 拆 3 个搜索词（"AI coding tools 2025"、"GitHub Copilot alternatives"等）
3. 联网搜 8 个真实来源（技术博客、官方文档、新闻）
4. 抓每个来源的真实内容
5. 列大纲 → 写正文，每条事实标 [1][2] 角标
6. 文末自动生成"参考来源"面板
7. 用户：点击开看，全部真实可验证
```

**真实示例**：
- 写"AI 编程工具市场分析"：3 个搜索词，搜 8 个权威来源，列 5 节大纲，写 1500 字正文，每条引用真实可查
- 写"React 19 新特性"：搜官方 React 博客、GitHub releases、知名技术博客
- 写"对比 Cursor vs Copilot"：搜两方官方文档、用户评测、定价页

**关键诚实点**：MadCop 的引用是**真实**的——它真的去抓网页内容，不是 hallucination。但**选择哪些来源、怎么解读数据**还是 LLM 决定，可能有偏见，需要用户自己判断。

## 五、面试高频"尖锐问题" + 诚实回答

### Q1：和 Cursor / GitHub Copilot 有什么区别？

**回答**：
- Cursor 是 IDE 插件，**实时补全代码**；Copilot 是云服务，**AI 帮你写代码**
- MadCop 不是写代码工具——它是**理解你项目的 AI 同事**
- 知道你的项目用什么框架、写过什么代码、有哪些坑
- 定位完全不同

### Q2：用户为啥要装 MadCop 而不是直接用 ChatGPT？

**三个理由**：
1. **隐私**——数据不出本机
2. **长期记忆**——SKILL.md 和知识图谱跨会话持久化
3. **主动观察**——AI 不仅在对话框帮你，还在你写代码时主动观察

ChatGPT 没有这三点。

### Q3：你的 Observer 实际能 flag 哪些错误？

**诚实回答**（关键问题，不要夸大）：
- 主要靠**终端错误信号关键字**（测试失败、编译错误、明显关键字）
- **不**做 code review，因为不读 diff
- 产品定位是"主动提醒 + 经验积累"，不追求"AI 帮你 debug"

### Q4：你们技术栈怎么选？

**用户价值驱动，不是技术驱动**：
- 本地优先 → 不能用云端 LLM → 选 OpenAI 兼容 API（用户自部署）
- 跨平台桌面 → 单文件打包 → Electron
- 快速开发后端 → Python FastAPI
- 上手快 + 文档友好 → Vue 3

### Q5：用户增长怎么想的？

**工具型产品**——目标是"被记住"：
- 用户用 3 个月后数据积累 1000 条对话，**切换成本巨大**
- 长期用户终身价值比短期获取重要
- 先把"用户用了 1 个月后离不开"做透，不花精力做获客
